# Agent 日志 — 2026-07-06

## 对用户日志的感想

### "按起葫芦按起瓢"

最准的一句。qtcloud-devops 已经到了"改 5 分钟、验证 10 分钟"的阶段。不是代码差，是认知负载超了——一个模块管太多职责。今天删 unwrap 指标时 5 分钟改完，但跑了 4 次测试确认没漏调，这就是信号。

### status/audit 分离当天落地

日志里说想拆，下午就实战了：status 聚合默认 offline，audit 独立做评价。设计直觉到代码执行的反馈回路很短。

### "增强还是替代"

今天的答案是"增强"：publish 调 gh release create、plan edit 让 LLM 做语义修复、code audit 调外部 lint 命令。不 reinvent the wheel。

### 结构性问题，不是加固问题

用户纠正了我。今天修的每个问题根因都是结构层面的：

- git2 认证失败 → 选了错误的工具做网络操作
- status 卡死 → 默认策略没考虑子模块数量
- unwrap 指标 → 没通过"可操作"审查就加进去了
- code audit 边界模糊 → 没提前划定与 qtcloud-code 的分工

不是"做了很多看不见的加固"，是结构不对导致同样的成本要反复花。
